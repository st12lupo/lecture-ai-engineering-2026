# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  素のLLMは講座固有の知識を持たないため、「3レベル」の意味について一般的な推測で答えるか「分からない」と回答した。一方、エージェントは自動的に `search_glossary` ツールで用語集（`glossary.json`）を検索し、「基礎・実装・発展」という講座固有の定義と該当する講義回を含めた正確な回答を返すことができた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - `uv run python -m app.agent --trace "LoRA とQLoRAの違いは？"`
    - `[tool call] search_glossary({'query': 'LoRA'})`
    - `[tool call] search_glossary({'query': 'QLoRA'})`
  - `uv run python -m app.agent --trace "第2回の内容から確認問題を 1問出して"`
    - `[tool call] make_quiz({'lecture': 2})`
- 1つの質問での LLM 呼び出し回数（`requests`）：
  2回（`requests=2`）。1回目に質問を解釈して必要なツール（`make_quiz` 等）を呼び出し、2回目にツールから返ってきた結果を受け取って最終的な回答文を生成している。
- 追加したツールと、docstring に書いた説明：
  追加したツール：`make_quiz(lecture: int) -> str`
  docstring の説明：
  ```python
  """指定した回の用語から1つを選び、確認問題と答えを返す。

  「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。
  """
  ```
  指定した回の用語からランダムに1つ選び、問題と解説のペアを生成するツール。docstring に利用用途を明記したことで、モデルが適切なタイミングで自律的に呼び出せるようになった。

## 宿題
- 取り組んだレベル：基礎
- やったこと：
  `app/agent.py` の `INSTRUCTIONS` から「必ず search_glossary で用語集を確認する」という指示文を削除し、演習と同じ質問（`"AIE2026の講座の宿題にある「3レベル」とは何ですか？"`）を `--trace` 付きで再実行して、ツールの呼び出し方と回答の変化を比較した。
- 結果：
  指示を削除する前は必ず回答前に `[tool call] search_glossary` が実行され用語集を参照していたが、削除後はツールが呼び出されず（`requests=1`、`tool_calls=0`）、素のLLMと同様に一般的な推測で回答するようになった。
- 気づき・疑問：
  ツールがコード上で登録されていても、システムプロンプト（`INSTRUCTIONS`）やツールの `docstring` の指示次第で、モデルがツールを使うかどうかの判断が直接左右されることを実感した。エージェントを狙い通りに動かすには、ツールの実装だけでなく適切なプロンプト指示の設計（ハーネス設計）が不可欠であると分かった。
