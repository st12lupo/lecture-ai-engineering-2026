## 宿題

- 取り組んだレベル：基礎
- やったこと：
  採点のモデル（`AIE_MODEL`）だけを `gemini-3.5-flash-lite`（既定）から `gemini-3.5-flash` に変え、同じ `lectures/04/labels.jsonl` と `data/eval/rubric.md` で再実行しようとした。
  `AIE_MODEL=gemini-3.5-flash uv run python -m app.judge --out lectures/04/judge_result_flash.json`
  ただし、Gemini API の無料枠のレート制限にかかり、変えた後の採点は最後まで実行できなかった。
- 結果：
  - 変える前（gemini-3.5-flash-lite）：根拠 9/9、範囲 10/10、ヒント 10/10、分かりやすさ 9/10、回の表示 10/10。総合 9/9、要確認 1 件（#05 根拠）
  - 変えた後（gemini-3.5-flash）：実行できず。10 件中 7 件目の途中で 429（RESOURCE_EXHAUSTED）になった
  - エラーの中身を確認すると、1 分あたりではなく 1 日あたりの上限（無料枠、`GenerateRequestsPerDayPerProjectPerModel-FreeTier`、1 モデルあたり 20 回/日）だった。採点は 1 回で 10 リクエスト使うので、試行を重ねるうちに上限を使い切っていた。リセットまで約 3 時間と表示された
- 気づき・疑問：
  - アプリは 429 を一律「1 分ほど待ってから再実行してください」と表示するが、実際は 1 日の上限だった。同じ 429 でも、1 分の上限か 1 日の上限かはエラー本文（quotaId）を見ないと分からない
  - LLM で採点すると、評価を回すたびに API の回数と料金を使う。件数 × 試行回数 × モデル数で効いてくるので、無料枠だとモデルの比較のような実験は 1 日に数回しかできない。評価のコスト（回数・時間）も記録しておく必要があると感じた
  - 上限はモデルごとに別なので、flash の上限に達しても flash-lite では採点できた。リセット後に、同じラベルで flash の採点をやり直して比べたい
